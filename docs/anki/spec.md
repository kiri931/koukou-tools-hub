# 覚える君 出題仕様

対象: `src/features/anki/`
この文書は **出題の仕方**（どう問い、どう答えさせ、どう次回に繋ぐか）だけを書く。
FSRS のスケジューリング式そのもの・IndexedDB のスキーマは対象外。

---

## 1. なぜ変えるのか

いまの覚える君は、最初の1回目から短答入力を求める。
用語を1つも知らない状態でいきなり打たせても、生徒は空欄のまま「わからない」を押す。
それは復習ではなく、ただの失敗体験になる。

そこで **初めて出会うカードは4択で「見て選ぶ」、2回目以降は自分で「思い出して書く」** に分ける。
選ぶのは再認（見覚えがあるか）、書くのは再生（思い出せるか）で、
再認を1回はさんでから再生に進むほうが、最初の1問で心が折れない。

あわせて、書けないときに何も足がかりがないのも問題なので、
**押したときだけ出るヒント** を用意する。押さずに解けたなら、それが一番いい。

---

## 2. 出題モード

カードは出題のたびに、**選択モード**か**記述モード**のどちらかになる。

| 判定 | モード |
|---|---|
| そのカードの `cardState` が無い、または `reps === 0` | 選択（4択） |
| それ以外（1回でも解いたことがある） | 記述（短答入力） |

- 判定基準は **カードごとの学習回数**。セッションの周回数ではない。
  用語集にあとから用語を足したとき、新しいカードだけが4択になる。
- 記述で不正解でも、選択モードには戻らない（`reps` は増えるため）。
  つまずいたカードは FSRS が短い間隔で出し直す。それで十分と判断した。

### 選択モードの見た目

- 問題文の下に、選択肢を **縦1列** に4つ並べる。ボタンは全幅。
  横並びの2×2にすると、スマホで選択肢が2行に折り返して読みにくい。
- 選択肢には `1` `2` `3` `4` の数字キーでも答えられる。数字はボタン内に表示する。
- 押した瞬間に採点へ進む。「送信」ボタンは置かない。
- 選んだあとの取り消しはできない。迷いも含めて記録に残したいため。

### 出題中はカテゴリを出さない（両モード共通）

以前は問題文の上にカテゴリのバッジを常時出していたが、やめた。
ヒントの1段階目がカテゴリなので、常に見えているとヒントを押す意味が無くなる。
選択モードでも、カテゴリが見えていると誤答を絞り込めてしまう。
**採点画面では出す**（答え合わせの場では隠す理由がない）。

### 記述モードの見た目

現状のまま（`Input` に打って Enter か送信ボタン）。変更なし。

## 3. 選択肢の作り方

正解1つ + 誤答3つ = 4つ。

1. **表示ラベルは `answers[0]`**（代表形）を使う。
   用語集の `answers` には「SNS（ソーシャル・ネットワーキング・サービス）」「SNS」
   「えすえぬえす」のような同義候補が並んでいる。ひらがな読みを選択肢に混ぜると
   「えすえぬえす」と「SNS」が並んで、答えが割れてしまう。
2. **誤答は同じ `topic` の他のカードの代表形から選ぶ。**
   用語集の topic は「情報社会の問題解決」など4カテゴリ。
   カテゴリを揃えないと「シグニファイア / 光の三原色 / 標本化 / 総当たり攻撃」のように
   分野がバラバラになって、消去法で当たってしまう。
3. 同 topic のカードが足りないときは、**同じデータセットの他のカードで補う**。
   それでも4つに満たない場合は、集まった数だけで出す（3択・2択になる）。
   カードが1枚しかなくて選択肢が作れないときは、**記述モードにフォールバックする**。
4. 正解と表記が重なる誤答は落とす。
   NFKC 正規化＋小文字化して一致するもの、および
   一方が他方を丸ごと含むものは使わない。
   正解が「整列アルゴリズム（ソート）」のとき「アルゴリズム」を誤答に混ぜない、ということ。
   選択肢の中に「より正しそうな2つ」があると、問題として成立しない。
   一方「探索アルゴリズム」は含みも含まれもしないので、誤答として使ってよい。
   同じ分野の並んだ概念どうしは、むしろ見分けさせたい相手になる。
5. 並び順は `カードID + reps` を種にした決定的なシャッフル。
   同じカードを同じ回数目で開いたら同じ並びになる（テストできる）が、
   カードが違えば正解の位置も変わる（位置で覚えられない）。

## 4. ヒント

**「ヒント」ボタンを押した回数だけ**、上から順に開く。押さなければ何も出ない。

| 段階 | 出すもの | 例 |
|---|---|---|
| 1 | カテゴリ（`topic`） | 情報社会の問題解決 |
| 2 | 文字数 | ○○○○○○（6文字） |
| 3 | 最初の1文字 | 問○○○○○ |

- 文字数・最初の1文字は **代表形 `answers[0]` から括弧書きを除いた形** で数える。
  「問題解決の手順（PDCAサイクル）」は「問題解決の手順」＝7文字として扱う。
- 段階3まで開いたらボタンは消える。
- **選択モードにはヒントを出さない。** 4択のうえヒントまで出すと答えが確定する。
- ヒントは1問ごとにリセットされる（次の問題に持ち越さない）。
- 開いた段階数はその問の採点に使う（次項）。**保存はしない。**
  「何回ヒントを見たか」をDBに貯めても、いまは見せる場所がない。

---

## 5. ヒント・選択が復習間隔に与える影響

自己採点（1 Unknown / 2 Hard / 3 Good / 4 Easy）はそのまま残す。
ただし **押せる上限を下げる**。

| 状況 | 上限 |
|---|---|
| 選択モードで正解 | 3（Good）まで。Easy は出さない |
| ヒントを1段階以上開いた | 2（Hard）まで。Good・Easy は出さない |
| 不正解 | 従来どおり 1 のみ |

- 4択で当てただけ、あるいはヒントを見て書けただけのカードを Easy にすると、
  FSRS が「よく覚えている」と判断して次回が数週間先になる。まだ覚えていない。
- 上限は **ボタンを出さないことと、受け取り側での丸め込みの両方** でかける。
  数字キーの入力からも同じ関数を通すので、キーボードで 4 を押しても Good になる。
- 上限がかかっているときは、その理由を1行で書く
  （例: 「選んで正解したので Easy は出しません」）。理由の無い制限は不親切。
- **正解したのに押せるボタンが1つしか残らないときは、ラベルを「次へ」にする。**
  ヒントを使って正解すると Hard だけが残るが、選ぶ余地が無いのに「Hard」と書いてあると
  自己評価を求められているように読める。実態は「次へ進む」操作なのでそう書く。
  記録される評価は Hard（2）のままで、変わるのは見た目だけ。
  不正解のときの「Unknown」1つは、そのままにする。
  こちらは「わからなかった」という意味を持つので、押す側にも伝わっていてよい。

## 6. 問題文に答えが混ざっている場合

用語集の一言説明には「頭文字を取って **PDCAサイクル** とも呼ばれる」のように
別名が書かれていることがあり、その別名は正答候補でもある。答えが問題に書いてある。

**出題時に自動で伏せる。**

- 問題文中に `answers` のいずれかと一致する部分があれば `〇〇〇` に置き換えて表示する。
- 長い候補から順に置き換える（「問題解決の手順（PDCAサイクル）」を先に処理してから
  「PDCAサイクル」を見る、の順）。
- 伏せ字は **常に `〇〇〇` の3文字**。答えの文字数に合わせない。文字数ヒントになるため。
- 1文字・2文字の候補は伏せない。「〇」「値」のような短い語は本文中の別の意味で
  出てくるほうが多く、伏せると文が壊れる。
- 採点画面では **伏せていない元の問題文** を出す。答え合わせの場では隠す理由がない。
- ひらがな読み候補（「もんだいかいけつのてじゅん」）も対象にする。
  漢字で書かれた本文とは一致しないので、実際に消えることはほぼ無いが、
  ひらがな表記の説明文が来たときに効く。

データ側（用語集の `oneLiner`）は書き換えない。
説明として自然な文を、覚える君の都合で崩す必要はない。

## 7. 状態

`StudySessionState` に足すもの。

```ts
mode: 'choice' | 'input';   // いまの問題の出題モード
choices: string[];          // 選択モードのときの選択肢（表示ラベル）。記述なら []
maskedQuestion: string;     // 出題用の問題文（答えが混ざっていれば伏せたもの）
hintLevel: number;          // 0〜3。この問で開いたヒントの段階数
usedHint: boolean;          // hintLevel > 0 の記録（採点時に参照）
choicePool: StudyQueueItem[]; // 誤答を作るための候補。データセット全体のカード
```

`choicePool` は期限切れのキュー（`queue`）とは別に、セッション開始時に
データセット全体を読んで持つ。期限切れが数枚しかない日に、その数枚だけで
4択を作ろうとすると選択肢が痩せてしまうため。

出題モード・選択肢・伏せ字は **問題が切り替わるときに1度だけ決めて状態に持つ**。
描画のたびに作り直すと、キーを押すたびに選択肢の並びが変わる。

問題が切り替わるたびに `hintLevel` は 0 に戻す。

## 8. 実装の置き場所

判定・生成のロジックは React の外に出し、単体テストを書く。

| ファイル | 中身 |
|---|---|
| `src/features/anki/lib/questionMode.ts` | モード判定、選択肢生成、決定的シャッフル |
| `src/features/anki/lib/hints.ts` | ヒント段階の生成 |
| `src/features/anki/lib/maskQuestion.ts` | 問題文の伏せ字 |
| `src/features/anki/lib/gradeCap.ts` | 採点の上限 |

`useStudySession.ts` はこれらを呼ぶだけにする。
`StudyView.tsx` は受け取って描くだけにする。

## 9. アクセシビリティ

- 選択肢のボタンは本文16px以上、コントラスト比 4.5:1 以上。
- 選択肢は **色だけで区別しない**。番号と文字で区別できるようにする。
- ヒントは開いたら `aria-live="polite"` で読み上げる。
- 数字キーの操作は補助であって、必須にしない。すべてクリック/タップで完結する。

---

## 10. やらないこと

- 誤答の選択肢を「よく取り違える組み合わせ（confusion）」から作ること。
  データが貯まってからでいい。いまは topic で足りる。
- ヒント使用回数の保存とダッシュボードへの表示。
- 選択モードでの「わからない」ボタン。4択に「わからない」を足すと、
  考える前にそれを押すだけになる。

## 11. 新しいカードの1日の上限（2026-10-22 追加）

試験用語集（ITパスポート 2287枚・基本情報 4280枚）を取り込むと、全部がその日の出題に入ってしまう。
そこで **まだ一度も答えていないカードは、問題集ごとに1日 N 枚まで** にした。

- 既定は20枚。設定タブの「1日に出す新しいカード」で変える（全問題集で共通の値、上限は問題集ごとにかかる）
- 0 は「復習だけ」。空欄で保存すると20に戻る。負の数・小数・数でない文字は保存させず理由を出す。9999枚まで
- 復習（一度でも答えたカード）は制限しない
- 1日の区切りは端末の時刻の0時（`countDue` の「今日」と同じ）
- 今日すでに出した枚数は、別に保存せず `reviews`（答えた記録）から数える。カードごとに最初の記録が今日の0時以降なら「今日の新しいカード」
- 画面：出題中と問題集のカードに「新しいカード 残り N 枚（今日）」、止まったら「今日の新しいカードはここまで」。完了画面に理由と残りの枚数を出す
- 判定は `lib/newCardLimit.ts`、テストは `lib/newCardLimit.test.ts`
