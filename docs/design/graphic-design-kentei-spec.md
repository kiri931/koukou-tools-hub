# グラフィックデザイン検定 対策教材 仕様

対象: `src/features/gd-kentei/`（新規）と `src/pages/study/graphic-design/`（新規）
この文書は **何を解説し、何を出題し、1級実技をどう練習させるか** を書く。
Astro のページ構成・デプロイ・SEO 文言は対象外（`AGENTS.md` に従う）。

---

## 1. 結論: 新規リポジトリを立てず、`koukou-tools-hub` の中に作る

理由は3つ。

1. **同じ形のものが既にある。** `/tools/calc-drill/`（計算技術検定ドリル）が
   「検定対策ドリル」としてこのリポジトリに入っている。グラフィックデザイン検定だけ
   別リポジトリにすると、同種のものが2箇所に散る。
2. **必要な部品が揃っている。** Astro + React、`LinkCard` / `SectionHeading`、Vitest、
   そして `覚える君`（`src/features/anki/`、FSRS による分散復習）。
   「解説を読む → 4択で解く → 間違えたものを復習する」は既存資産の組み合わせで作れる。
3. **1ツール1リポジトリ1Worker の原則は「独立して育つツール」向け**で、
   このリポジトリは元々「小さめの学習コンテンツを束ねる場所」という例外を持っている。

置き場所は次のとおり。

| URL | 中身 |
|---|---|
| `/study/graphic-design/` | 6分野の解説（読み物）＋用語辞典の入口 |
| `/study/graphic-design/<分野>/` | 分野ごとの解説本文 |
| `/study/graphic-design/glossary/` | 用語辞典（検索・分野で絞り込み） |
| `/tools/gd-kentei/` | 4択ドリル（3級・2級） |
| `/study/graphic-design/jitsugi/` | 1級実技の類題（指示書・指示図・支給データの配布） |

`koukou-jouhou/src/lib/site-links.ts` に1行足し、
`koukou-tools-hub/src/lib/site-links.ts` に同じ1件を写す（あちらが親）。

## 2. 決まっていること（前提）

この3つは確認済みで、以後ひっくり返さない。

- **公開する問題文はすべて書き下ろす。過去問の問題文・選択肢は1文字も転載しない。**
  過去問は「どの分野から、どういう聞き方で、どの用語が出るか」の分析にだけ使う。
- **1級実技は本番と同じ環境を前提にする。** Illustrator / InDesign、指定フォントは
  ヒラギノ明朝W3・ヒラギノ角ゴシックW3（Win は MS 明朝・MS ゴシック）、
  支給データは text(txt) / illust(jpg, eps) / image(tif, jpg)。
- **解説は用語辞典レベルまで作り込む。** 4年分の出題語をすべて拾って用語集にし、
  `覚える君` にも流し込めるようにする。

## 3. 実測した過去問の構造（2026-09-07 時点）

`https://zenkoukyo.or.jp/index_kentei/exam_result/` から5本のPDFを取得して確認した。

| PDF | 年度・回 | ページ | 問題本文のテキスト |
|---|---|---|---|
| `26gd_kekka.pdf` | 令和3・第26回 | 79 | **抽出できない**（問題部分がスキャン画像） |
| `27gd_kekka.pdf` | 令和4・第27回 | 81 | 抽出できる |
| `28gd_kekka.pdf` | 令和5・第28回 | 97 | 抽出できる |
| `29gd_kekka.pdf` | 令和6・第29回 | 92 | 抽出できる |
| `30gd_kekka.pdf` | 令和7・第30回 | 87 | 抽出できる |

第26回だけ OCR が要る。**第27〜30回の4年分（3級・2級・1級筆記 × 各75設問 = 900設問）を
まず正とし、第26回は後から足す。**

### 3.1 出題の形（4年分・3級2級1級すべて共通）

- 問1〜問15。各問に設問①〜⑤。**選択肢はすべて Ａ・Ｂ・Ｃ・Ｄ の4択。**
- 受検者は15題から**10題を選んで**解答する（50設問）。11題以上解くと失格。
- 筆記60分。合格は60点以上。
- **正答一覧が巻末に付いている**（例: 第30回3級 問1 ①Ｄ ②Ａ ③Ｄ ④Ｃ ⑤Ｂ）。

### 3.2 分野の割り当ては固定されている

| 問 | 分野 |
|---|---|
| 問1〜問3 | 企画・マーケティング・デザイン |
| 問4〜問6 | 写真 |
| 問7〜問9 | 編集レイアウト |
| 問10〜問11 | 写真製版 |
| 問12〜問13 | 印刷 |
| 問14〜問15 | 製本 |

**解説資料はこの6分野で切る。** 章立てを自分で考える必要はない。

### 3.3 設問には2つの型がある

読んだ限り、各問の①〜④は「用語を答える穴埋め・単答」、⑤は
「次の記述で正しい／間違っているものを選びなさい」の記述判定になっている場合が多い。
この2型を出し分けられるようにする。

- **用語型**: 説明文があり、当てはまる用語を4択から選ぶ。
  （例の作り方: 「墨流しと呼ばれ水面上の流れ模様を紙に転写する技法」→ マーブリング）
- **記述判定型**: 4つの記述のうち正しい／間違っているものを1つ選ぶ。
  「正しいものを選びなさい」と「間違っているものを選びなさい」の両方があり、
  **どちらを問われているかを見落とすのが失点源**なので、画面上で強調する。

### 3.4 図が要る設問がある

3級でも「三脚の上部についている、次の写真の名称を選びなさい」のように
**図版が前提の設問**がある。類題でこれを作るときは写真を使わず、
`codex-illustration-generator` スキルで SVG の図解を起こす（雲台、絞り、面付け、
折丁、綴じ方、トンボなど）。

  用語集に載せてよい。定義文は自分の言葉で書く。

## 5. データ設計

### 5.1 分野

```ts
// src/features/gd-kentei/lib/fields.ts
export type FieldId =
  | 'planning'    // 企画・マーケティング・デザイン
  | 'photo'       // 写真
  | 'layout'      // 編集レイアウト
  | 'prepress'    // 写真製版
  | 'printing'    // 印刷
  | 'binding';    // 製本
```

`問1〜問15` との対応表もここに持つ（模擬試験の組み立てに使う）。

### 5.2 用語辞典

```ts
export interface GdTerm {
  id: string;            // 'nombre'
  term: string;          // 'ノンブル'
  reading: string;       // 'のんぶる'  … 検索と並べ替えに使う
  field: FieldId;
  short: string;         // 1行の定義。カードとツールチップに出す
  body: string;          // 数行の解説。Markdown 可
  related: string[];     // 他の term.id
  figure?: string;       // 図解SVGのパス
  levels: ('3' | '2' | '1')[];  // どの級で出たか
  seenIn: string[];      // ['30-3-7-2', ...] 出題箇所の識別子のみ。問題文は持たない
}
```

**`seenIn` には出題箇所の識別子だけを入れ、過去問の本文は入れない**（§4）。

用語は分野ごとに JSON で持つ（`src/features/gd-kentei/data/terms/<field>.json`）。
1ファイルが大きくなりすぎるのを避け、分野単位で差分が読めるようにするため。

### 5.3 問題（すべて書き下ろし）

```ts
export interface GdQuestion {
  id: string;
  field: FieldId;
  level: '3' | '2' | '1';
  type: 'term' | 'statement';        // §3.3 の2型
  polarity?: 'correct' | 'incorrect'; // statement のとき「正しいもの」か「間違っているもの」か
  stem: string;                       // 問題文
  choices: [string, string, string, string];  // A〜D
  answer: 0 | 1 | 2 | 3;
  explanation: string;                // なぜその答えか。全選択肢に触れる
  termIds: string[];                  // 解説へ戻るリンク
  figure?: string;
}
```

### 5.4 テストで守ること

`calc-drill` と同じ考え方で、**データが増えたときに崩れていないか**を診断テストで見る
（`*.diagnostic.test.ts`）。

- 全問題の `answer` が `choices` の範囲内にある
- 選択肢4つに重複がない
- `termIds` がすべて実在する用語を指している
- `explanation` が空でない、かつ**正解以外の3つの選択肢すべてに言及している**
- 用語の `related` が実在の `id` を指している（リンク切れゼロ）
- **分野ごとの問題数が偏っていない**（本番の問数配分 3:3:3:2:2:2 に対して、
  どの分野も最低20問。下回ったらテストで警告する）

## 6. 画面

### 6.1 解説（`/study/graphic-design/<分野>/`）

- 本文16px以上、`max-w-3xl`、縦余白 `py-12 sm:py-16`（`AGENTS.md` の既定）。
- 用語の初出はその場で `<GdTermLink>` にし、押すと定義が開く。
  ページ遷移させない（読んでいる途中で飛ばすと戻ってこない）。
- 章の終わりに「この分野の問題を解く」ボタン。分野を絞ったドリルへ入る。
- **見出しに意味のない英大文字を使わない。**

### 6.2 用語辞典（`/study/graphic-design/glossary/`）

- 読みでの絞り込み（インクリメンタル検索）＋分野タブ。
- 各カードに `short` と分野、`levels`（3級/2級/1級のバッジ）。
- **色だけで級を区別しない。** バッジに必ず文字を入れる。

### 6.3 ドリル（`/tools/gd-kentei/`）

3つのモードを持つ。

1. **分野別ドリル** — 分野を選んで10問。1問ごとに正誤と解説を出す。
2. **模擬試験** — 本番の形をそのまま再現する。問1〜問15（各5設問）を出し、
   **受検者に10題を選ばせる**。60分のタイマー。60点で合否判定。
   本番で「11題以上解くと失格」なので、**11題目を開こうとしたら止める**。
3. **復習** — 間違えた問題だけを出す。

`type: 'statement'` の問題では、**「正しいもの」か「間違っているもの」かを
問題文とは別の帯で明示する。** 本番の失点源なので、ここは目立たせてよい。

### 6.4 覚える君との接続

用語集を `覚える君` の glossary 形式へ変換する関数を1つ置く
（`src/features/gd-kentei/lib/toAnkiGlossary.ts`）。
**覚える君側のデータ形式は変えない。** 変換だけをこちら側に持つ。

## 7. 1級実技の類題

### 7.1 本番の課題の形（第30回で実測）

- 指示書確認15分 ＋ 実技90分。仕上がりA4（210×297mm）、裁ちしろ3mm。
- 支給データ: text 6点（1, 2, 3, 4, data1, data2）／illust 6点（jpg, eps）／image 6点（tif, jpg）。
- 指定フォントは Mac がヒラギノ明朝W3・ヒラギノ角ゴシックW3、Win が MS 明朝・MS ゴシック。
- 1pt = 0.35mm。罫は指定がなければ内罫。写真同士は毛抜き合わせ。
- 文字組みは全て禁則処理。段落改行は1字下げ、括弧始まりは2分アキ。
  行頭禁止（句読点・中黒・波ダッシュ・疑問符・感嘆符・反復記号・受け括弧・促音・拗音・長音）、
  行末禁止（起こし括弧・ぶら下げ）、疑問符と感嘆符の次は2分アキ。
- 2字以上の算用数字は半角、2字以上のアルファベットはカーニング。
- 右上に主催団体名・検定名・受験番号を、10pt/行送り12pt・受験番号18pt半角、
  墨100%＋白0.25mmの袋文字で入れる。
- **選択問題**が1問ある。①ロゴマーク（正円φ55mm、CMYK、カタカナ/ひらがな/英字を最低2点）
  か ②作表（W64×H37mm、内罫0.25mm墨100%、8pt白文字、行送り10pt、明朝）の**どちらか一方**。
  選ばなかった方にはダミーデータを置く。両方作ると選択問題が0点になる。

### 7.2 類題として作るもの（1セット）

過去問の**構造だけを踏襲し、題材は自分で決める**（本番は「世界のグルメシリーズ」だったので、
別の題材にする。例: 日本の伝統色、地元の祭り、校内の部活動紹介）。1セットの中身:

```
public/gd-jitsugi/<セット名>/
  shijisho.pdf        指示書（2ページ）
  shijizu.pdf         指示図（グレーで配置位置を示した図）
  checklist.pdf       自己採点チェックリスト
  text/   1.txt 2.txt 3.txt 4.txt data1.txt data2.txt
  illust/ *.svg *.png   … 6点
  image/  *.jpg         … 6点
  README.txt          配布物の一覧と、本番との違い
  <セット名>.zip       上記一式
```

**支給する写真・イラストは自作か、商用利用可・改変可のものに限る。**
出典を `README.txt` に必ず書く。

1セット目（`dento-iro`）では写真を使わず、**すべて SVG から自動生成した自作画像**にした。
本番は illust が jpg と eps、image が tif と jpg だが、eps/tif に変換する道具が
この環境に無いため svg/png/jpg にしている。**練習の中身（配置と文字組版）は変わらない**ので、
その旨を `README.txt` と配布ページに書いて差を明示している。

**主催団体名は本番の団体名を使わない。** 実在の団体の課題を装わないため、
練習用の名前（「グラフィックデザイン検定 練習課題」）にしてある。

### 7.3 指示書・指示図の作り方

**当初は `kentei-print` と同じ `pdf-lib` + `@pdf-lib/fontkit` で作るつもりだったが、やめた。**
手元にある日本語フォントが IPAmj明朝（46MB）しかなく、サブセット化すると
文字が抜け（`image` が `m e` になる等）、サブセットを切ると **PDF 1本が31MB** になった。

いまは **HTML を書いて Chrome のヘッドレスに印刷させている**（実測 150〜460KB）。

```sh
tools/gd-jitsugi/make-data.mjs   # 支給データ（qlmanage で SVG→PNG、sips で PNG→JPEG）
tools/gd-jitsugi/make-pdf.sh     # 指示書・指示図・チェックリスト（Chrome --print-to-pdf）
```

ヘッドレスの Chrome は印刷後も終了しないので、スクリプト側で待って kill している。

- 指示書は「全体に関わる諸注意」→「選択問題」→「全体部分の指定」→
  「上段/中段/下段部分の指定」の順。本番と同じ並びにする。
- 指示図は各要素の枠をグレーで示し、mm 寸法を入れる。SVG で作って PDF に載せる。

### 7.4 採点

自動採点はしない（Illustrator の成果物を Web で採点するのは無理がある）。
代わりに **自己採点チェックリスト**を配る。

- 本番の配点の考え方に合わせ、「配置」「文字組版」「色指定」「寸法」に分けた項目表。
- 「すべてが配置されていれば合格できる」わけではない、と本番の報告書が明記している。
  チェックリストにもその趣旨を1行入れる。
- 印刷用の1枚PDF（`checklist.pdf`）と、画面で押せるチェックリストの両方を用意する。

## 8. 作る順番

依存の少ないものから。1〜3は並行してよい。

1. **コーパス整備**（`.local-corpus/`、非公開）
   27〜30回の3級・2級・1級筆記を、`{級, 問番号, 設問番号, 分野, 出題語, 型, 正答}` の
   構造化データにする。**問題本文は残さない。** 26回は OCR して後から足す。
2. **用語辞典**（6分野）— コーパスから出題語を抜き、定義を書き下ろす。
   分野ごとに分割して並行で書ける。
3. **図解SVG** — §3.4 の図が要る用語のぶん。`codex-illustration-generator` に投げる。
4. **解説ページ**（6分野）— 2の用語をつないで読み物にする。
5. **ドリル**（分野別 → 復習 → 模擬試験の順）。模擬試験が一番重い。
6. **1級実技セット**（まず1セット。回して確かめてから2セット目）。
7. `site-links.ts` に登録（メインサイト → hub の順）。

## 9. 受け入れ基準

- 6分野すべてに解説ページがあり、**どの分野も用語20語以上・問題20問以上**ある。
- 診断テスト（§5.4）が全て通る。
- 模擬試験モードで、10題を選んで60分で解き、採点まで到達できる。
  **11題目を開こうとすると止まる。**
- 1級実技セットが1つ完成し、Illustrator で実際に開いて課題として成立することを確認済み。
- 公開ページのどこにも過去問の問題文・選択肢が無い（`grep -a` で確認する）。
- コントラスト監査（`shared/tools/contrast-audit.mjs`）を本番URLに対して通す。
- スマホ幅（375px）で解説・辞典・ドリルが横あふれしない。

## 10. やらないこと

- 過去問そのものの掲載（§4）。
- 1級実技のブラウザ上での作図・自動採点。本番のソフト操作が身につかないうえ、
  実装が数倍重い。
- 準1級を別枠として扱うこと。準1級は受検枠ではなく1級の合格ラインが2段階あるだけなので、
  模擬試験の判定に「1級合格 / 準1級合格 / 不合格」の3段階を出すにとどめる。
